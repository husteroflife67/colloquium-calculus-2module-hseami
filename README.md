# Предел — подготовка к Коллоквиуму I

Русскоязычный автономный тренажёр по математическому анализу. React 19, TypeScript, Vite, Tailwind 4, KaTeX. Регистрация, сервер и API не нужны.

## Запуск

Node.js 22+ (проверено на 24.19), npm 11.

```sh
npm ci --cache /tmp/predel-npm-cache
npm run dev -- --port 5173
```

```sh
npm run typecheck
npm test
npm run build
npm run preview -- --port 4173
```

Сборка в `dist/`; для деплоя разместите содержимое каталога на любом статическом хостинге. По умолчанию путь — корень домена (включая Netlify). Для GitHub Pages сборка с `GITHUB_PAGES=true` использует путь репозитория; ссылки на PDF учитывают `import.meta.env.BASE_URL`.

## Возможности

Обзор реальных результатов, восемь тематических блоков, определения с флеш-картами, доказательства с постепенным раскрытием, собственные черновики, вопросы принимающего, авторская практика. Все 21 вопрос программы связаны с материалами. Просмотр ничего не осваивает: общий/тематический процент = число объектов с самооценкой «Знаю» / число объектов в соответствующем наборе. Чек-лист независим от процента. Вопросы имеют отдельную самооценку; она не повышает прогресс определения/теоремы.

Билет сохраняет seed и полный состав. Доступны равномерный подбор, приоритет слабых объектов, выбранные темы. Учебный режим допускает помощь и паузу; симуляция скрывает определения до вызова и короткое утверждение до второго принимающего. Общий бюджет подготовки и определений 30 минут, определения до 5, второй ответ до 40, допзадача 20+10, предел 2 часа. Вызов на определения возможен вручную раньше или автоматически на 25-й минуте. Сэкономленное время возвращается подготовке. Баллы кратны 0,5; база из 8 и дополнительные баллы показываются отдельно. Допзадача выбирается однократно с порогом 6/6,5. Тренажёр не вычисляет неизвестную итоговую оценку.

## Контент и источники

- `public/sources/program.pdf`: пользовательский файл «теория-1.pdf», программа Коллоквиума I.
- `public/sources/notes.pdf`: пользовательский «конспект.pdf», лекции 2026/27.
- `src/content/types.ts`: типизированная схема.
- `src/content/numbers.ts`, `sequences.ts`, `functions.ts`, `practice.ts`: материал отдельно от UI, стабильные ID, тема, связи с вопросами программы, источник, происхождение, статус проверки и заметки.

Авторские объяснения/доказательства/уточнения/решения помечены `generated`, даже если формулировка взята из курса. `self_reviewed` не означает формальную верификацию или авторство преподавателя. Проверка A: логика, B: кванторы/техника, C: отдельная критическая рецензия; результаты в `review_notes` и `MATH_REVIEW.md`. Нумерация источников сохранена, страницы не выдуманы. Риман включён без обязательного доказательства. Внешние источники не использовались.

Официального закрытого пула, семинарских листков и подготовленного Markdown среди вложений нет. Все 16 задач — авторская имитация. Правила коллоквиума взяты из пользовательского задания. Расхождения источников и ограничения см. `TODO_CHECK.md`.

## Данные

Прогресс, черновики и история хранятся в localStorage, текущий билет — в sessionStorage (перезагрузка вкладки поддерживается). Оценки уточнений хранятся отдельно, но входят в JSON-экспорт. Настройки позволяют экспорт/импорт JSON схемы 1; до замены проверяются ID, оценки и структура. При ошибке данные сохраняются. Сброс требует подтверждения. Хранилища браузера могут быть очищены; регулярно экспортируйте копии. Данные не отправляются на сервер. Автоматической проверки свободного математического ответа нет; оценки выставляет пользователь.

`src/engine.ts` содержит независимую от UI логику билетов, баллов, таймеров и импорта; будущий слой синхронизации может заменить адаптер хранения, сохранив стабильные ID и схему.

## Проверки

Vitest проверяет ID, DAG зависимостей, покрытие 21 вопроса, синтаксис KaTeX, генерацию и повторение билетов, ограничения баллов и допзадач, таймеры и импорт. Эти тесты не доказывают математическую истинность содержания. Фактические результаты запуска приводятся в итоговом отчёте задачи.

Браузерные проверки: `npm run test:e2e` (6 сценариев Playwright). В облачной среде используется установленный `/usr/bin/chromium`; на другой машине установите Chromium и задайте `CHROMIUM_PATH=/полный/путь/к/chromium`. Проверяются сохранение черновиков и карточек, все этапы билета и порог 6/6,5, история/повтор, экспорт/импорт, автоматические таймеры, мобильное чтение и тёмная тема.

Проверено в текущей среде: типы и production-сборка успешны; 15 unit/content-тестов и 6 браузерных сценариев прошли. История и результаты в приложении изначально пустые: тестовые данные из изолированного браузерного контекста не поставляются пользователю.

## Дополнительные уточнения

В `src/content/extra-questions.ts` добавлены 27 прицельных вопросов: кванторы, достаточные и необходимые условия, контрпримеры, оценки погрешности и выбор параметров. Они связываются с исходными определениями и фактами в `src/content/index.ts`. Всего 207 уточнений; у каждого есть строгий ответ, подсказка, критерий достаточности, типичная ошибка и происхождение. Старые ID и сохранения не изменены; существующий интерфейс раскрытия и самооценки используется без изменений. Дополнения — авторские, не официальный пул.

## GitHub Pages

`.github/workflows/deploy.yml` проверяет типы и тесты, собирает приложение и публикует `dist` после push в `main` либо ручного запуска workflow. В GitHub Settings → Pages выберите Source → GitHub Actions. Если Pages ещё не включён, необходимо однократное включение через настройки или GitHub API с соответствующими правами. Workflow использует штатный `GITHUB_TOKEN`, дополнительные секреты для публикации не требуются.

Локальная проверка именно сборки для подпапки:

```sh
GITHUB_PAGES=true npm run build
npm run test:pages
```

Тест открывает production-сборку по пути репозитория, проверяет загрузку интерфейса/формул и обоих PDF. Для GitHub Pages ожидаемый адрес — https://husteroflife67.github.io/colloquium-calculus-2module-hseami/ (работает только после успешной публикации). `npm run build` без переменной по-прежнему создаёт сборку для корня домена.
