# Предел — подготовка к Коллоквиуму I

Русскоязычный автономный тренажёр по математическому анализу. React 19, TypeScript, Vite, Tailwind 4, KaTeX. Регистрация, сервер и API не нужны.

## Запуск

Node.js 22+ (проверено на 24.19), npm 11.

```sh
npm ci --cache /tmp/predel-npm-cache
npm run dev -- --port 5173
```

```sh
npm run typecheck
npm test
npm run build
npm run preview -- --port 4173
```

Сборка в `dist/`; для деплоя разместите содержимое каталога на любом статическом хостинге. По умолчанию путь — корень домена (включая Netlify). Для GitHub Pages сборка с `GITHUB_PAGES=true` использует путь репозитория; ссылки на PDF учитывают `import.meta.env.BASE_URL`.

## Возможности

Обзор реальных результатов, восемь тематических блоков, определения с флеш-картами, доказательства с постепенным раскрытием, собственные черновики, вопросы принимающего, авторская практика. Все 21 вопрос программы связаны с материалами. Просмотр ничего не осваивает: общий/тематический процент = число объектов с самооценкой «Знаю» / число объектов в соответствующем наборе. Чек-лист независим от процента. Вопросы имеют отдельную самооценку; она не повышает прогресс определения/теоремы.

Билет сохраняет seed и полный состав. Доступны равномерный подбор, приоритет слабых объектов, выбранные темы. Учебный режим допускает помощь и паузу; симуляция скрывает определения до вызова и короткое утверждение до второго принимающего. Общий бюджет подготовки и определений 30 минут, определения до 5, второй ответ до 40, допзадача 20+10, предел 2 часа. Вызов на определения возможен вручную раньше или автоматически на 25-й минуте. Сэкономленное время возвращается подготовке. Баллы кратны 0,5; база из 8 и дополнительные баллы показываются отдельно. Допзадача выбирается однократно с порогом 6/6,5. Тренажёр не вычисляет неизвестную итоговую оценку.

## Контент и источники

- `public/sources/program.pdf`: пользовательский файл «теория-1.pdf», программа Коллоквиума I.
- `public/sources/notes.pdf`: пользовательский «конспект.pdf», лекции 2026/27.
- `public/sources/corrected-guide.pdf`: дополнительный исправленный конспект по материалам Н. Белянко от 19.10.2026. Его нумерация не заменяет программу, а сам файл не является подтверждением официального пула.
- `src/content/types.ts`: типизированная схема.
- `src/content/numbers.ts`, `sequences.ts`, `functions.ts`, `practice.ts`: материал отдельно от UI, стабильные ID, тема, связи с вопросами программы, источник, происхождение, статус проверки и заметки.

Авторские объяснения/доказательства/уточнения/решения помечены `generated`, даже если формулировка взята из курса. `self_reviewed` не означает формальную верификацию или авторство преподавателя. Проверка A: логика, B: кванторы/техника, C: отдельная критическая рецензия; результаты в `review_notes` и `MATH_REVIEW.md`. Нумерация источников сохранена, страницы не выдуманы. Риман включён без обязательного доказательства. Внешние источники не использовались.

Официального закрытого пула, семинарских листков и подготовленного Markdown среди вложений нет. Все 16 задач — авторская имитация. Правила коллоквиума взяты из пользовательского задания. Расхождения источников и ограничения см. `TODO_CHECK.md`.

## Данные

Прогресс, черновики и история хранятся в localStorage, текущий билет — в sessionStorage (перезагрузка вкладки поддерживается). Оценки уточнений хранятся отдельно, но входят в JSON-экспорт. Настройки позволяют экспорт/импорт JSON схемы 1; до замены проверяются ID, оценки и структура. При ошибке данные сохраняются. Сброс требует подтверждения. Хранилища браузера могут быть очищены; регулярно экспортируйте копии. Данные не отправляются на сервер. Автоматической проверки свободного математического ответа нет; оценки выставляет пользователь.

`src/engine.ts` содержит независимую от UI логику билетов, баллов, таймеров и импорта; будущий слой синхронизации может заменить адаптер хранения, сохранив стабильные ID и схему.

## Проверки

Vitest проверяет ID, DAG зависимостей, покрытие 21 вопроса, синтаксис KaTeX, генерацию и повторение билетов, ограничения баллов и допзадач, таймеры и импорт. Эти тесты не доказывают математическую истинность содержания. Фактические результаты запуска приводятся в итоговом отчёте задачи.

Браузерные проверки: `npm run test:e2e` (11 сценариев Playwright). В облачной среде используется установленный `/usr/bin/chromium`; на другой машине установите Chromium и задайте `CHROMIUM_PATH=/полный/путь/к/chromium`. Проверяются сохранение черновиков и карточек, все этапы билета и порог 6/6,5, история/повтор, экспорт/импорт, автоматические таймеры, мобильное чтение и тёмная тема.

Проверено в текущей среде: типы и production-сборка успешны; 36 unit/content-тестов и 11 браузерных сценариев прошли. История и результаты в приложении изначально пустые: тестовые данные из изолированного браузерного контекста не поставляются пользователю.

## GitHub Pages

`.github/workflows/deploy.yml` проверяет типы и тесты, собирает приложение и публикует `dist` после push в `main` либо ручного запуска workflow. В GitHub Settings → Pages выберите Source → GitHub Actions. Если Pages ещё не включён, необходимо однократное включение через настройки или GitHub API с соответствующими правами. Workflow использует штатный `GITHUB_TOKEN`, дополнительные секреты для публикации не требуются.

Локальная проверка именно сборки для подпапки:

```sh
GITHUB_PAGES=true npm run build
npm run test:pages
```

Тест открывает production-сборку по пути репозитория, проверяет загрузку интерфейса/формул и обоих PDF. Для GitHub Pages ожидаемый адрес — https://husteroflife67.github.io/colloquium-calculus-2module-hseami/ (работает только после успешной публикации). `npm run build` без переменной по-прежнему создаёт сборку для корня домена.

## Дополнительный исправленный конспект

`src/content/guide.ts` связывает разделы дополнительного PDF с каждым из 21 вопроса: в карточках доступны ссылки на точные разделы и страницы. Добавлены два авторских варианта разбора — Больцано–Вейерштрасс делением отрезка и критерий Коши функции через чередование путей — и два уточняющих вопроса с ответами. Варианты раскрываются внутри существующих материалов, не создают новых объектов освоения и не меняют исходные ID/историю/состав билетов. На этом этапе уточнений стало 209; после добавления официальных 43 карточек — 290.

Доказательства и ответы помечены generated/self_reviewed, выполнена отдельная критическая C-рецензия. Ссылки на дополнительный PDF не превращают авторские задачи и объяснения в материал преподавателя. Полной независимой математической проверки всех разделов нового PDF не заявляется.

Карта соответствий и границы источника: `docs/CORRECTED_GUIDE_REVIEW.md`. Топология ℝᵈ, o/O и итерации Ньютона из PDF не добавлены в обязательную программу. В вопросе 6 сохранён радикал из официального перечня; новый конспект подтверждает наличие другого ньютоновского примера, но не устраняет расхождение источников.

## Официальный перечень устной части и ревью от 29 октября 2026

`public/sources/definitions.pdf` — пользовательский «определения-1.pdf»: 43 официальных вопроса на определения **и формулировки**. В `src/content/official-definitions.ts` сохранены номера, исходные запросы, ссылки на обе страницы и развёрнутые авторские ответы. В разделе «Определения» по умолчанию показаны 43 официальные карточки; шесть прежних вспомогательных доступны через фильтр состава. Всего объектов 87 и уточнений 290. Все прежние 60 ID сохранены. Общий процент может снизиться из-за расширения знаменателя, старые оценки и история не удаляются.

Для вопросов №2 и №12 созданы новые ID: прежние карточки описывали только грани и вложенность, а новые вопросы требуют максимум и принцип вложенных отрезков. Старое «Знаю» не переносится автоматически на расширенные ответы. Новые билеты выбирают четыре карточки только из официальных 43; старые билеты со вспомогательными карточками продолжают импортироваться и повторяться по сохранённому составу.

Официальность относится к запросам в перечне, а не к авторским ответам: они остаются generated/self_reviewed. Закрытого пула задач и коротких утверждений по-прежнему нет. Матрица покрытия: `docs/OFFICIAL_DEFINITIONS_REVIEW.md`; отдельная критическая C-рецензия прежних и новых ответов — `MATH_REVIEW.md`.

## Согласованные функции

- **На сегодня**: сначала назначенные повторения, срок которых подошёл, затем новые официальные формулировки, обязательная теория и практика. После самостоятельного ответа и самооценки «Знаю» интервалы растут: 1→3→7→14→30 суток. «Не знаю» — через 10 минут; «Частично»/«Повторить» — через сутки со сбросом серии. Открытие ответа не назначает повторение и не меняет прогресс. Сутки — 24 часа; используется время устройства. Самооценка карточки в библиотеке также обновляет её расписание. Старые оценки без расписания сохраняются; сроки появляются после следующей самооценки. Пропуск действует только в текущем сеансе.
- **Устный экзаменатор**: выбор темы и официальной формулировки/доказательства, собственный черновик, 3–6 тематических уточнений, подсказки, строгие ответы и явная самооценка. Итоги учитывают только оценки текущей беседы. Черновик и оценки вопросов сохраняются; текущий шаг беседы после перезагрузки начинается заново. Приложение не распознаёт речь, не обещает автоматической проверки произвольного доказательства и не добавляет баллы к билету.

Обе функции согласованы пользователем. Установка/PWA и офлайн-режим не добавлялись. `src/repetition.ts` и `src/oral.ts` содержат чистую тестируемую логику. `Data.schedules` — необязательное поле схемы 1; старые JSON без него совместимы, новые расписания входят в экспорт и проверяются при импорте.

В симуляции на этапе определений отображаются официальные вопросы, а не готовые формулировки ответов. Образцы доступны только через помощь учебного режима; в режиме экзамена помощь скрыта.
